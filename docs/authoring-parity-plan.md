# Authoring parity plan

What remains between the editor and everything a New Centurions scenario can hold, and between its screens and Providence's. The original 1.3.2 binary stays the authority; Providence
(`C:\Users\Eric\Documents\ChatGPT\New project 2`) is a source of ideas and generic code only, never of Realmz rules. Each phase is merged on its own, and `target/release` is rebuilt at the end of every
turn so the Godot project always runs (see "Keeping the Godot project current").

## What Providence has that this editor lacks (from a read-only survey)

| Area | Providence | This editor |
|---|---|---|
| Resource codecs | PICT decode and encode (palette, dither, PackBits), cicn decode and encode (32 x 32, 1-bit mask), snd decode and encode (8-bit mono, MACE decode), TEXT and styl (styl runs), STR# lists | Decodes PICT and cicn for display only; nothing is written |
| Import and export of media | PNG, JPG, WebP, BMP in; WAV in; folder and archive import; export to PNG, WAV, UTF-8 text; a prepare, review, commit flow | none |
| Previews | Icon preview wherever an icon id is held, sound play buttons, 8-frame animation preview, picture zoom | Icons only on some pages; no sound or animation preview |
| Maps | Create and duplicate maps, painting tools, dungeon features, event cells, regions; no delete, resize or object layer | Floor tiles, look and light, regions, triggers |
| Timed events | Full editor (all 11 fields) | Disable only |
| Monsters | Tabs (Overview, Attacks, Spells, Items, Saves, Conditions, Links), several fields to a row, `id · name` fields with a searchable picker that previews the icon, picture or sound | One long page; bare numbers |
| Treasure | Record list, item pool with search, 20 ordered slots with art | Twenty bare number pairs, opens on an empty row |

## Findings that settle unknowns without testing

- **Code 113.** Every reader of the word is `centerpictlarge`'s marker test, the script assignment and the save and load of it. A nonzero number only stops the party marker being fetched; no picture is loaded by it. The number has no other meaning.
- **Code 128.** `spelleffectoutdoors` draws eight `cicn` icons, 12000 + 8 x animation + frame, in a square of the given size whose top-left corner sits on the top-left corner of the map square, offset by half the size. Its x is the column (word 2) and its y the row (word 3), both taken from the current view's origin; the delay (word 5) is passed to the original's `delay` after each frame when it is not 0. What is not yet read is the unit of `delay` (expected 1/60 s) and whether a column or row outside the view is clipped.
- **Movie.** The original has no movie format. "Movie" is the scrolling-text window of code 62 and the opening prologue: a `TEXT` and a `styl` resource of the same number, searched in the scenario then the game, and a missing one crashes the game. Supporting it means authoring `TEXT` and `styl`.

## P2 Resource authoring (including the scrolling-text "movie")

1. Codecs in `centurions-format`: PICT encode (indexed, PackBits), cicn encode, snd encode and decode, TEXT and styl read and write, STR# write for 801 and 802 (item names). Decode and display what is already read.
2. Resource-fork writer: rebuild `Scenario.rsrc` on export from the project's resource edits, preserving every resource the editor did not touch, byte for byte.
3. A project holds the resource edits as typed edits with identities, like every other edit, so undo, save and reopen work.
4. Import and export in the workbench: pictures (PNG, JPG, BMP in; PNG out), icons, sounds (WAV in; WAV out), scrolling texts (UTF-8 in and out, Mac Roman stored) with a style editor, in a prepare, review, commit dialog.
5. A resource browser with scenario, installation and stock scopes, where a reference to a missing resource offers to import one.
6. Problems stops warning about a resource once it is authored; the existing warnings for codes 27, 62 and 128 stay for the rest.

**P2a status (resource-fork writer and scrolling texts).** `resource_fork.rs` reads a classic resource fork and writes it back keeping the data order, the type and reference order, names, attributes and the reference bytes the format leaves to the system; the scenario's, `Cargo Pod.rsrc`'s and `Tacticals.rsrc`'s forks write back byte for byte, and an AppleDouble wrapper keeps its other entries. `resources.rs` applies three typed edits (`resource_change` for any `TEXT`, `styl`, `PICT`, `cicn`, `snd ` or `STR#`; `scroll_text` for a text with its style runs, which cuts runs past a shorter text; `scroll_text_remove`) to `Scenario.rsrc`, and the adapter lists and reads the texts with the steps that show them (`scroll_texts`, `scroll_text`). A Texts page (Story, between Messages and Combat) lists the texts by their first words, edits the text and its runs (start, font, size, bold, italic, underline, colour), shows a scroll-window preview and the steps that use it, adds and removes texts by number, and imports and exports plain text; a code 62 step has a Choose text picker (the record picker, extended). The exported `Scenario.rsrc` was read back with an independent parser: the new texts are there, the removed one is gone and every other resource is the same. The UI was designed in Gesso first (`design/resources.canvas`: the reference picker, the Texts page and the import dialog). Still to do in P2: picture, icon and sound import (the import dialog), `STR#` names, the resource browser, and the generic searchable picker, each built when its step needs it. The rail now drops its names below 920 pixels of height, because it holds twelve workspaces.

**P2b status (pictures, icons and sounds).** `codecs.rs` writes the three resources from ordinary files: a color icon (`cicn`, an 8-bit palette image with a 1-bit mask, laid out as the game's own), a picture (`PICT`, a version 2 PackBitsRect with a palette) and a sound (`snd `, format 1, 8-bit mono, any rate up to 65,535), with median-cut colour reduction and optional dithering, three ways to fit an image to a size, and a WAV reader (8, 16, 24 and 32-bit integer and 32-bit float). The decoders that read the game's own resources read these back (round-trip tests), and an icon imported through the adapter was found by the `icons` request afterwards. The adapter prepares an import (`import_prepare`: the converted bytes, a preview of what the game would hold, colours kept, how far colours moved, whether the number is free), lists what the scenario and the game hold (`resources`) and exports one to a PNG or WAV (`export_resource`); an import becomes a `resource_change` edit holding the bytes. A Resources page (Records, with a Choose workflow built from the same browser) shows a grid of the icons, pictures and sounds with a large preview, scopes (this scenario, the game, both), a number filter, Import, Export and Remove; an import dialog shows the file and its conversion side by side with the options of its kind; every icon, sound and picture field has a Choose button that opens the browser as a picker. The Gesso design is `design/resources.canvas`. Checked in the original game (see "Imported resources in the original" below): an imported picture and an imported icon are read and drawn by it. Still to do in P2: `STR#` names (the scenario's item names, 801 and 802), and a Problems check for an imported resource of a size the game never draws.

## Keeping the Godot project current

The editor is tested by running the Godot project, so `target/release/centurions-adapter.exe` must match the source. The adapter reports an interface number and the workbench refuses a different one with a message, instead of failing in the debugger. Run from the Godot editor, the workbench launches a copy of the adapter, so building it again never fails because the editor is open. Whoever changes an operation the workbench reads raises `INTERFACE` (`crates/centurions-editor/src/session.rs`) and `ADAPTER_INTERFACE` (`godot/src/native_bridge.gd`) together and rebuilds `target/release` before the turn ends.
